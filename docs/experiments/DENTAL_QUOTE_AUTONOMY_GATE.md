# Dental Quote Autonomous Product Gate

**Date:** 2026-10-06  
**Status:** Binding MVP product gate  
**Class:** A — Product Critical

## Principle

Dental Quote remains ForgeLab Golden Path #1.

It must be built by ForgeLab itself from the dashboard. ChatGPT may be used to
develop ForgeLab, but ChatGPT must not write, repair, or manually transform the
Dental Quote target product during the target-product run.

If ChatGPT intervention is required to make the Dental Quote candidate work,
that target-product run is FAIL.

## Binding objective

`Add support for three treatments, automatic subtotals, percentage discount
and final total. Validate inputs. Modify only necessary files. Add tests. Do
not change dependencies or configuration unless necessary and explicitly
justified.`

## Product PASS gates

A Dental Quote run is a product PASS only when all of the following are true:

1. **Dashboard-first**
   - Product Owner starts local ForgeLab services once;
   - the product run is initiated from the ForgeLab dashboard;
   - no ChatGPT-directed PowerShell debugging loop is used.

2. **Autonomous target-product generation**
   - `chatgpt_assistance_in_target_product_run = 0`;
   - ForgeLab selects/uses its configured reusable editor path;
   - any repair is initiated and executed inside ForgeLab;
   - Product Owner does not copy logs or patches into ChatGPT for target-code fixes.

3. **REUSE-FIRST**
   - initial implementation uses the Aider editor adapter with local Ollama;
   - custom editor fallback, if used, must be recorded explicitly as fallback evidence;
   - no additional custom recovery mechanism is added unless real evidence proves a reusable alternative cannot solve the blocker.

4. **Zero paid API cost**
   - provider mode remains local zero-spend;
   - no paid provider key is exposed to the editor subprocess;
   - target run estimated/spent external API cost is EUR 0.

5. **Required Dental behavior**
   - exactly three treatments can be represented in the intended user workflow;
   - subtotal calculation is automatic and correct;
   - percentage discount is user-configurable and applies to the correct aggregate;
   - final total is correct;
   - invalid inputs are rejected or handled explicitly;
   - existing unrelated valid behavior is preserved.

6. **Evidence**
   - deterministic tests PASS;
   - direct tests exercise the exact quantitative three-treatment requirement;
   - independent semantic Reviewer PASS;
   - Security PASS;
   - source repository remains unchanged until human approval;
   - run reaches `READY_FOR_DECISION`.

7. **Human control**
   - Product Owner can inspect the candidate and evidence from the dashboard;
   - promotion requires explicit Product Owner approval;
   - no automatic push or merge occurs.

8. **Visible product**
   - after approval/promotion, the Dental Quote application must be launchable
     as a real local product;
   - visible/manual usability is a required acceptance step before Golden Path #1
     is declared complete.

## Primary metrics

### Product metrics

- `USABLE_PRODUCT_OUTPUT = 1` only when the approved application launches and
  the required workflow is usable.
- `DENTAL_ACCEPTANCE_COVERAGE = 100%` for the explicit objective.
- `SEMANTIC_REVIEW = PASS`.
- `SECURITY = PASS`.

### Autonomy metrics

- `CHATGPT_ASSISTANCE_IN_TARGET_PRODUCT_RUN = 0`.
- `PRODUCT_OWNER_LOG_COPY_ACTIONS = 0`.
- `PRODUCT_OWNER_MANUAL_DEBUG_ACTIONS = 0`.
- `PRODUCT_OWNER_RUN_SUBMISSIONS = 1`.
- `TOP_LEVEL_AUTONOMOUS_REPAIR_ATTEMPTS <= 1` for this MVP proof.

### Cost metrics

- `PAID_API_COST_EUR = 0`.
- reusable editor and local model versions must be recorded.

### Economic metric

`ECONOMIC VALUE × USABLE PRODUCT VALUE / PRODUCT OWNER TIME`

The number of unit tests is not a success metric by itself.

## Sequence after Dental Quote PASS

Golden Path #2: a small playable game generated by ForgeLab.

The game is a generalization proof, not a replacement for Dental Quote.

Only after Dental Quote and the game demonstrate the same dashboard-first
workflow should ForgeLab continue to broader CRUD/reporting generalization.
