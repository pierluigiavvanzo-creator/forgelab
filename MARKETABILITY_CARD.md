## 1. ICP
**NOT YET VALIDATED.**

ForgeLab is the primary product and is defined as a governed multi-agent software-development control plane. The exact paying segment is not yet supported by customer evidence in the canonical project state.

## 2. Pain
Product hypothesis: reduce the manual effort required to turn a software objective into a working, tested, reviewed result while preserving deterministic verification, bounded repair, human approval and safe promotion.

Customer severity/frequency of this pain is **not yet commercially evidenced**.

## 3. Current alternative
**UNKNOWN / requires explicit benchmark by target ICP.**

Likely comparisons must be selected only after ICP choice; do not assume that generic coding agents, IDE assistants or internal development workflows are the relevant buying alternative.

## 4. Value proposition
Target workflow:
`OBJECTIVE -> PROJECT/REPO CONTEXT -> PLAN -> IMPLEMENT -> TEST -> BOUNDED REPAIR -> REVIEW -> WORKING PREVIEW -> HUMAN APPROVAL -> PROMOTION`.

The commercial value hypothesis is fewer Product Owner/engineering intervention minutes per usable software outcome, with stronger governance and evidence.

## 5. Willingness-to-pay evidence
**NONE CANONICALLY VERIFIED YET.**

Usability or Golden Path success does not equal willingness to pay.

## 6. Acquisition path
**UNKNOWN.**

Must be designed after selecting the first ICP. Prefer a repeatable channel that does not require sustained Product Owner manual prospecting.

## 7. Time-to-value
Technical time-to-value should be measured as time from objective submission to verified working preview/output for a bounded real application.

The current priority is to validate this through Golden Path applications, beginning with Dental Quote after stabilization.

## 8. Delivery economics
Track:
- model/API/runtime cost per completed job;
- human review minutes;
- failed/repair attempts;
- infrastructure cost;
- support burden.

The current zero-cost local Ollama path is useful technically but is not itself proof of scalable commercial economics.

## 9. Compliance/security constraints
Preserve isolation, independent review/security, deterministic verification and explicit promotion gates. Commercial pressure must not bypass these controls.

## 10. Differentiation hypothesis
Governed end-to-end execution with bounded repair and human-controlled promotion must outperform simpler alternatives on measurable usable-output rate, operator time and reliability.

## 11. Proof metric
Near term:
- complete Golden Path objective achieved;
- real working preview/output;
- intervention count/minutes;
- repair count;
- deterministic tests and semantic review;
- no promotion without approval.

Commercial proof begins only when a defined ICP values this outcome and provides transaction-level evidence.

## 12. Next commercial evidence
After fresh Golden Path success, choose one narrow first ICP and validate whether the demonstrated workflow solves a frequent/costly enough job to justify a paid pilot.

## Commercial discipline
Do not expand the multi-agent platform surface merely because more agents/features are possible. Every major capability must improve the probability, speed, reliability or economics of a sellable end-to-end software outcome.
